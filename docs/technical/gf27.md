# QRtransfer 2.0 experimental optical coding

GF(27) = GF(3)[x]/(x^3+2x+1); each field symbol is three ternary coefficients. A systematic group has at most 12 data blocks and 15 Cauchy repair rows. Distinct rows are MDS: any group-size valid rows recover the group, including parity-only recovery. This is finite erasure coding, not a rateless fountain. Sequence modulo the carousel identifies the row; no back-channel. Groups interleave in the repair sweep. Six source bytes map to 11 base-27 symbols packed in seven wire bytes; tail padding is checked. Critical flag 0x02 distinguishes the codec; old receivers reject it. Sender and receiver use the same existing QR/WASM pipeline. GF27 animation export is intentionally disabled until it shares the new scheduler.

Binary mode remains the default. Original file bytes are never transformed by ambiguous CVNSS conversion. CVNSS4.0 Audit-safe Studio remains optional text analysis, not a lossless compression claim. SHA-256 checks the restored original bytes; the existing FNV container checksum is a non-cryptographic integrity check, not authentication. The link is unencrypted. Only transfer authorized files.

Evidence: benchmarks/gf27-isolate.json records the executed deterministic JavaScript synthetic-loss experiment (byte-by-byte equality, not camera). tests/gf27.test.ts exercises field arithmetic, parity-only, reorder, duplicate, wire, Vietnamese filename and SHA256 fail-closed behavior. benchmarks/compare-codecs.ts produces paired seeded CPU-only comparisons; GitHub Actions uploads reports per OS. Neither benchmark establishes camera goodput. For physical validation, use the same file, settings, lighting and device pairs, 10 repeats per mode, record SHA-256 at both ends, capture/decoded FPS, wall-clock goodput and failure rate. Keep actual device data separate from historical Decimen records. Browser/PWA offline tests and 64 MiB physical test remain outstanding.
